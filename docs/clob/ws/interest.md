# clob/ws/interest.rs 阅读笔记

## bitflags! { ... } 说明

这段 `bitflags! { ... }` 用来定义一个**位标志集合类型** `MessageInterest`，用 `u16` 的每一位表示一种订阅“兴趣”。核心目的：用一个整数高效地表示“我关心哪些消息类型”。

详细讲解（对应你的代码）：

- `bitflags!` 宏来自 `bitflags` crate，它会生成一个结构体类型 `MessageInterest`，并自动实现常用运算（`|`、`contains`、`is_empty` 等）。
- `pub struct MessageInterest: u16` 表示底层存储是 `u16`。最多 16 个独立的标志位。
- 每个 `const` 是一个**位掩码**：
  - `BOOK = 1` 表示第 0 位。
  - `PRICE_CHANGE = 1 << 1` 表示第 1 位。
  - `TICK_SIZE = 1 << 2` 表示第 2 位。
  - 以此类推。
- 组合标志：
  - `MARKET` 把多个 market 相关位通过 `|` 组合成一个“集合”。
  - `USER`、`ALL` 也是组合集合。
- `const NONE = 0` 表示不关心任何消息。
- 这样就可以用一个 `MessageInterest` 同时表达多个订阅兴趣，比如：
  - `MessageInterest::BOOK | MessageInterest::TRADE` 表示既关心订单簿又关心成交。

为什么要这样做：

- **空间/性能高效**：用一个整数表达多个布尔开关。
- **组合/判断简单**：`contains`、`is_empty`、`bits()` 让判断逻辑清晰。
- **线程安全方便**：后面 `InterestTracker` 用 `AtomicU16` 存储这些位标志，线程间更新只需原子位运算。

在这个文件中的具体用途：

- `MessageInterest::from_event_type` 将服务端 event_type 字符串映射到对应的 bit flag。
- `InterestTracker` 通过原子位运算 `fetch_or` 合并兴趣集合。
- `parse_if_interested` 根据当前兴趣决定是否解析/转发消息，避免不必要的解析。

## 并发中的内存序（Ordering）详解（面向零基础）

### 为什么需要“内存序”

在多线程环境里，编译器和 CPU 可能会重排指令以提升性能。这样一来：

- 一个线程“写入”的数据，另一个线程可能看不到最新值。
- 写入的顺序，在线程之间看到的顺序可能不一致。

为了让线程之间的读写“有序且可见”，Rust 提供了原子类型和“内存序（Ordering）”。

### 原子操作（Atomic）的直观理解

原子操作可以理解为：

- “这个读/写不可被打断”
- “这个读/写对其他线程有一定的可见性保证”

但“有多强的保证”，就取决于你传入的 Ordering。

### 常见的内存序：从弱到强

1. **Relaxed**（最弱）
   - 只保证这个原子操作本身是原子的。
   - 不保证“顺序”或“可见性”。
   - 适合统计计数器等对顺序无要求的场景。

2. **Release / Acquire**（常用组合）
   - **Release** 用在写入线程：表示“我之前的写入，别让它跑到这个写之后”。
   - **Acquire** 用在读取线程：表示“我之后的读取，别跑到这个读之前”。
   - 这两个配合起来，形成“先写后读”的可见性保证。
   - 直观效果：
     - A 线程用 Release 写；B 线程用 Acquire 读到新值后，就能看到 A 在线程里“之前的写入”。

3. **AcqRel**
   - 一次操作同时具备 Acquire + Release 语义（既读又写）。

4. **SeqCst**（最强）
   - 所有线程看到的原子操作顺序是全局一致的。
   - 最安全但性能最差。

### 用生活化的比喻

- **Release** 就像“把公告贴在墙上并上锁”，保证这个公告之前写在板子上的内容已经完成。
- **Acquire** 就像“看到公告后再进房间”，保证进入房间后能看到公告之前所有内容。

### 在本代码中的意义

这里：

- `add()` 用 `Ordering::Release`：写入兴趣标记时，告诉系统“我之前做的更新要对外可见”。
- `get()` 用 `Ordering::Acquire`：读取兴趣标记时，保证读取到新值后，能看到对应更新。

这种 `Release` + `Acquire` 的组合是**并发场景下最常见、且足够安全**的写法。

### 选型建议（简单版）

- 只是计数、统计：用 `Relaxed`。
- 线程之间需要“先写后读”的可见性：用 `Release`/`Acquire`。
- 需要全局强顺序：用 `SeqCst`。
